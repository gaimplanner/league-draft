<objective>
Build the backend composite score calculation service and API endpoints. The service normalizes heterogeneous score types (1-5 scales, timed runs, catch counts) to comparable 0-100 values, aggregates coach ratings and tryout station scores per player, blends them using configurable weights, classifies players into tiers based on data completeness, and exposes rankings with per-player breakdowns via REST endpoints.

Purpose: This is the core computation engine that turns raw evaluation data from Phases 2 and 3 into draft-ready composite scores. Without this, coach ratings and tryout scores remain isolated data silos.

Output: CompositeScoreService class, 4 API endpoints (calculate, list, detail, promote), validators, transformers, URL routing.
</objective>

**Class: CompositeScoreService**

All methods are @classmethod. Import from models: Season, CoachRating, StationScore, GroupPlayer, EvaluationTemplate.

**Method: calculate_composite_scores(season_id: UUID, weights: dict) -> list[dict]**
Main entry point. Steps:
1. Load season with template (select_related)
2. Call `_gather_players(season)` to get all unique players (union of GroupPlayer names and CoachRating player names for the season)
3. Call `_aggregate_coach_ratings(season, template)` to get per-player coach scores
4. Call `_aggregate_tryout_scores(season, template)` to get per-player tryout scores
5. Call `_blend_and_rank(coach_scores, tryout_scores, weights, template)` to produce final composites
6. Return list of dicts sorted by tier (full-data first, then coach-only, then tryout-only), then by composite_score descending within each tier

**Method: _gather_players(season) -> list[dict]**
Union of:
- GroupPlayer records for the season (first_name, last_name, bib_number, group_player_id)
- CoachRating records for the season (player_first_name, player_last_name) where the name doesn't match any GroupPlayer
Returns list of `{"first_name": str, "last_name": str, "bib_number": int|None, "group_player_id": UUID|None}`
Use case-insensitive name matching (iexact) to link coach ratings to tryout players.

**Method: _aggregate_coach_ratings(season, template) -> dict[str, dict]**
Key = normalized "first_last" lowercase string for matching.
For each submitted CoachRating in the season:
- Extract scores dict (keyed by category ID)
- Look up category definitions from template.coach_categories
- For each category score: normalize to 0-100 using the category's min/max scale (normalizeScore equivalent: value / max * 100)
- Calculate weighted average of all normalized category scores (equal weight per category for v1)
- Return dict mapping player_key to `{"raw_scores": {cat_id: raw_value}, "normalized_scores": {cat_id: norm_value}, "aggregate": float, "coach_name": str (coach email), "status": str}`

**Method: _aggregate_tryout_scores(season, template) -> dict[str, dict]**
Key = normalized "first_last" lowercase string.
For each player with StationScore records in the season:
- Group scores by station_id
- For each station, look up station definition from template.stations
- For each score field in the station: normalize based on field type:
  - `scale`: value / max * 100 (higher is better)
  - `count`: value / max * 100 (higher is better)
  - `time`: (max - value) / (max - min) * 100 (lower is better, invert). Use percentile-based range calculation: exclude bottom/top 5% of all values for that field across all players to handle outliers. If fewer than 5 values, use raw min/max.
- Calculate per-station aggregate (average of normalized field scores)
- Return dict mapping player_key to `{"stations": {station_id: {"raw_scores": {}, "normalized_scores": {}, "aggregate": float}}, "aggregate": float, "stations_scored": int, "stations_total": int}`

**Method: _blend_and_rank(coach_scores, tryout_scores, weights, template) -> list[dict]**
`weights` structure: `{"coach_rating": int, "tryout_score": int, "station_weights": {station_id: int} (optional)}`
- coach_rating + tryout_score must sum to 100
- If station_weights provided, use them to weight individual station aggregates; otherwise equal weight per station
- For each player:
  - Determine tier: "full" (has both), "coach_only" (coach but no tryout), "tryout_only" (tryout but no coach)
  - If full: composite = (coach_aggregate * coach_weight/100) + (tryout_aggregate * tryout_weight/100)
  - If coach_only: composite = coach_aggregate (use coach score as-is, NOT weighted)
  - If tryout_only: composite = tryout_aggregate (use tryout score as-is, NOT weighted)
  - Track `is_partial_tryout` flag: player has some but not all station scores
- Sort: full-data players by composite descending, then coach-only by composite descending, then tryout-only by composite descending
- Assign rank within each tier (1, 2, 3... per tier)
- Return list of composite result dicts

**Method: _normalize_score_value(value, field_def, all_values_for_field=None) -> float|None**
Mirror the logic from `src/utils/scoreNormalization.ts`:
- Handle None/null: return None
- For scale/count (higher is better): `(value / field_def['max']) * 100`, clamp 0-100
- For time (lower is better): use percentile-based min/max from all_values_for_field if available, otherwise field_def min/max. `((max_val - value) / (max_val - min_val)) * 100`, clamp 0-100. If min == max, return 50.

**Method: _calculate_percentile_range(values, percentile=5) -> tuple[float, float]**
Filter nulls, sort, return (p5, p95) values. If fewer than 5 values, return (min, max).

**Method: get_player_detail(season_id: UUID, player_key: str, weights: dict) -> dict**
Return full breakdown for a single player: coach rating details (per-category raw + normalized), tryout details (per-station, per-field raw + normalized), composite calculation breakdown.

**Method: promote_player(season_id: UUID, player_key: str, target_tier: str) -> None**
Store tier override. Add a simple model or use Season-level JSON field for tier overrides: `{"player_key": "target_tier"}`. Use `Season.tier_overrides` JSONField (will need migration OR store in composite result and pass through).

**Decision:** Store tier overrides in a new JSONField on Season model: `composite_tier_overrides = JSONField(default=dict)`. This avoids a new model for a simple key-value map. Add this field via migration.

**Additional notes:**
- Use `@transaction.atomic` on calculate_composite_scores for consistency
- Use `select_related` and `prefetch_related` to avoid N+1 queries
- Player key format: f"{first_name.lower().strip()}_{last_name.lower().strip()}" for matching across CoachRating and GroupPlayer
- Log calculation events using existing `get_logger` pattern
